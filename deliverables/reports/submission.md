# Amazon Appstore submission preparation

Package ID is com.planavora.app. Target Fire tablets. Amazon ended support for the Amazon Appstore on general-purpose Android phones in August 2025. [Amazon distribution announcement](https://developer.amazon.com/apps-and-games/blogs/2025/02/upcoming-changes-to-amazon-appstore-for-android-devices-and-coins-program)

Use a free app listing and configure a one-time entitlement for planavora.premium. £4.99 is the proposed UK test price. Configure the SKU, regional pricing and test users in the developer console. The app displays the price returned by Amazon. Build with -PplanavoraReceiptEndpoint=https://your-verifier.example/amazon after a receipt verification service is deployed. The service must verify the receipt, SKU, purchase type and cancellation status through Amazon RVS with the shared secret stored on the service. The Android client expects HTTP 200 and a JSON object with valid=true and sku equal to planavora.premium. The client keeps purchases disabled in builds without that endpoint. Test Amazon restore, cancellations, pending purchases, unavailability and purchase fulfilment on the target device before launch. [Amazon IAP implementation](https://developer.amazon.com/docs/in-app-purchasing/iap-implement-iap.html) · [Amazon testing](https://developer.amazon.com/docs/in-app-purchasing/iap-testing-overview.html)

Use the public [GitHub repository](https://github.com/lanray07/Planavora) for the developer URL, the [GitHub support page](https://github.com/lanray07/Planavora/blob/main/SUPPORT.md) for the support URL and the [GitHub privacy draft](https://github.com/lanray07/Planavora/blob/main/PRIVACY.md) after policy approval. A support email field requires an actual monitored address supplied by the developer. Do not use the repository URL where Amazon requires an email address.

The metadata files contain translation drafts for the 15 documented listing options. App languages and storefront languages have different coverage. Spanish (Mexico) uses the Latin American Spanish interface. Indian English uses the British English interface in the first capture configuration. The console is the final authority for target countries and eligible models. [Amazon localisation options](https://developer.amazon.com/docs/app-submission/distribute-your-app-internationally.html)

Use the transparent 114 × 114 and 512 × 512 PNG icons. The store-assets directory contains eight raw Fire tablet captures and eight editable compositions per documented storefront variant. Use 3–10 approved PNG or JPEG images in a supported size per storefront listing. The Fire HD 10's native 1200 × 1920 output fits the documented portrait sizes. The store text drafts use terms such as event planner, party checklist, guest list, RSVP tracker and event budget tracker. Search term volumes and marketplace ranks have not been measured. Use the productivity or lifestyle category that most closely matches the options shown for the app in the console. [Amazon details and asset requirements](https://developer.amazon.com/docs/app-submission/appstore-details.html)

Planavora uses standard Amazon signing. Amazon applies its signature in the standard upload flow. For a developer-signed APK or a local DevTest build that must match a registered certificate, identify the local keystore and alias. Provide passwords through the signing prompt or a secure local secret store. [Amazon signing and App Tester guidance](https://developer.amazon.com/docs/in-app-purchasing/iap-get-started.html) · [Android APK signing](https://developer.android.com/tools/apksigner)

For App Tester, configure the Planavora entitlement as `planavora.premium` and export the tester JSON from the Developer Console. Install App Tester on the Fire device and provide the HTTPS URL or hosting access for the sandbox verifier. Amazon RVS Cloud Sandbox accepts any non-empty shared-secret value. For production receipt verification, enter the real Developer Console shared key directly into the verifier host's secret store. For Live App Testing, provide the Amazon account email used on the test tablet and access to the Planavora Developer Console listing. [Amazon IAP test modes](https://developer.amazon.com/docs/in-app-purchasing/iap-testing-overview.html) · [RVS Cloud Sandbox](https://developer.amazon.com/docs/in-app-purchasing/rvs-cloud-sandbox.html)

App Tester purchase and restore passed on the Fire HD 10 with a locally authored entitlement file and a temporary HTTPS sandbox verifier. The tablet configuration was restored and the temporary verifier was stopped. Complete the Developer Console entitlement setup, production verifier deployment and Live App Testing before enabling production purchases.

For Live App Testing, create `planavora.premium` as an Entitlement and choose **Submit to Test**. Download Planavora's `AppstoreAuthenticationKey.pem` from **Upload Your App File → Additional information → View public key** and package it under `app/src/main/assets/`. Add the Amazon account used on the Fire test device as a tester in the restricted test track. [Amazon LAT setup](https://developer.amazon.com/apps-and-games/blogs/2025/10/how-to-choose-the-right-tool-for-IAP-testing) · [Appstore public key](https://developer.amazon.com/docs/appstore-sdk/appstore-sdk-troubleshooting.html)

Deploy `scripts.receipt_verifier:application` behind HTTPS with the real Amazon shared key stored as `AMAZON_RVS_SECRET`. Use a separate deployment for the restricted test, set `AMAZON_RVS_LAT=1`, and point the test APK to its URL via `-PplanavoraReceiptEndpoint`. This mode calls Amazon's production RVS and accepts test receipts for the beta entitlement. The customer-facing verifier leaves both test-mode flags unset and accepts production receipts only. Run `python -m unittest scripts.test_receipt_verifier -v` to check the receipt acceptance rules locally. [Amazon RVS environments](https://developer.amazon.com/docs/in-app-purchasing/iap-testing-overview.html)
